# Отчёт о подготовке Next.js-версии

Дата: 2026-10-19

## Что создано

Подготовлен отдельный проект `funeral-site-next` на Next.js App Router и TypeScript на основе исходного ZIP-проекта Figma Make.

- Перенесены существующие React-компоненты и CSS-стили.
- Сохранена визуальная структура сайта и существующие разделы.
- Созданы отдельные URL: `/`, `/services`, `/funeral`, `/products`, `/prices`, `/about`, `/info`, `/faq`, `/contacts`, `/legal`.
- Добавлены базовые метаданные и русская локаль документа.
- Добавлены генераторы `robots.txt` и `sitemap.xml`.
- Индексация намеренно закрыта до замены заглушек и подключения настоящих данных.
- Добавлен `.env.example` без реальных секретов.
- Добавлен README с командами запуска и ограничениями текущей версии.
- Обновлено сообщение формы: интерфейс не сообщает, что заявка успешно отправлена, потому что серверная обработка пока не подключена.

## Проверки, выполненные в этой среде

Успешно прошли 10 статических проверок и отдельная проверка синтаксиса TS/TSX:
1. package.json существует.
2. App Router root page существует.
3. Layout и глобальные CSS существуют.
4. Все девять дополнительных маршрутов имеют `page.tsx`.
5. Старое hashchange-навигационное поведение удалено.
6. Навигация направляет на реальные URL.
7. Форма не показывает ложное сообщение «Запрос принят».
8. Индексация закрыта на подготовительном этапе.
9. Пример переменных окружения существует.
10. README явно описывает незавершённые CMS и формы.
11. TypeScript transpile-проверка синтаксиса прошла для 14 файлов TS/TSX без синтаксических ошибок.

## Ограничения проверки

Команда `npm install` не завершилась в отведённое время. В этой среде зависимости Next.js не установлены, поэтому `npm run build` и полноценная TypeScript-проверка фактически не запускались. Следовательно, production-сборка пока **не подтверждена**. После распаковки проекта на машине с доступом к npm необходимо выполнить:

```bash
npm install
npm run build
```

Если сборка выдаст ошибки, исправить их до дальнейшего этапа.

## Что пока НЕ реализовано

- Payload CMS и админ-панель.
- PostgreSQL и миграции.
- Реальное сохранение заявок.
- Telegram/email уведомления.
- Реальные телефон, адрес, цены и подтверждённые сведения о компании.
- Настоящая политика обработки персональных данных.
- Production-развёртывание и домен.

Текущая версия — подготовительная миграция интерфейса, не опубликованный сайт и не готовый к приёму реальных заявок релиз.

## Следующий этап

После подтверждения сборки подключить Payload CMS + PostgreSQL, затем реализовать коллекции услуг, товаров, цен, страниц и заявок. Для уведомлений нужны настройки Telegram и/или email; секреты передавать только через серверные переменные окружения.
