# Аудит production-подготовки

Актуальное руководство с пошаговым планом размещения, миграций, резервного
копирования и восстановления находится в
[docs/production-deployment.md](docs/production-deployment.md).

## Что проверено и изменено

- Подтверждены версии Next.js 16.3.8, Payload 3.91.0, PostgreSQL 16,
  React 19.3.1 и Sharp 0.35.5. Next.js обновлён с 15.4.11 из-за критических
  production advisory; Payload 3.91.0 разрешает Next `>=16.3.3 <17`.
- Сохранены App Router, Payload Admin, коллекции и существующий интерфейс.
  Публичное чтение каталога ограничено опубликованным контентом; чтение
  `Leads` требует авторизации, публичное создание через Payload CRUD закрыто.
- Усилены проверки формы: canonical Origin/HTTPS и IP доверенного proxy обязательны
  в production; добавлен ограниченный по памяти лимит 5 запросов на IP за 15
  минут. Для публичного запуска также необходим общий лимит на proxy/WAF.
- Уведомления остаются после сохранения заявки; повторная отправка доступна
  администратору без создания дубликата. Надёжной фоновой очереди нет.
- Добавлен readiness endpoint с проверкой PostgreSQL, healthcheck приложения,
  `npm ci`, удаление dev-зависимостей из production image, non-root пользователь
  и прямой запуск процесса Next.js в Docker.
- Production schema push отключён; миграции должны храниться в `migrations/` и
  применяться явно. Сейчас миграций в репозитории нет.
- Создано руководство по VPS, DNS/HTTPS placeholders, Compose, миграциям,
  backup/restore, обновлению и обработке сбоев.

## Результаты проверок

- `npm run build` — успешно на Next.js 16.3.8.
- `npx tsc --noEmit` — успешно.
- `npm run lint` — ошибок нет; остаются 7 предупреждений в существующем UI
  (`<img>` и неиспользуемые переменные).
- `npm run test:leads` — 14 тестов прошли.
- `npm run verify:scaffold` — успешно.
- Docker Compose конфигурация проверена. Финальный production image собран;
  проверены non-root user, healthcheck, отсутствие `.env`/`.env.example` и
  отсутствие dev ESLint пакета. Само приложение/БД из образа не запускались.
- `npm audit --omit=dev` после безопасных обновлений: 5 умеренных upstream
  advisory в цепочке Payload Postgres adapter / Drizzle Kit / esbuild без
  применимого автоматического исправления; high/critical runtime advisories
  устранены. Полный audit также находит 5 high в development ESLint dependency
  tree, который не копируется в production image отдельной установкой runtime
  зависимостей.

## Блокеры до публичного запуска

1. Создать и проверить Payload migrations на изолированной копии базы; не запускать
   первую production-схему автоматически.
2. Выбрать и укрепить VPS, настроить действительные secrets и canonical HTTPS URL.
3. Настроить trusted reverse proxy с перезаписью `X-Real-IP`, HTTPS и общей защитой
   частоты запросов.
4. Настроить постоянные хранилища и off-site backup; проверить восстановление
   PostgreSQL и медиа в тестовом окружении.
5. Проверить вход в админку, каталог, загрузку изображений, тестовую заявку и
   контролируемых Telegram/SMTP получателей.
6. Проверить юридические тексты и правила хранения персональных данных.
   Индексация поиском намеренно выключена до утверждения публичного содержимого.

VPS, DNS, HTTPS, production migration, восстановление backup, Payload Admin login,
публичная форма и реальные уведомления не запускались и не подтверждены.
Сайт не готов к публичному production-запуску.
