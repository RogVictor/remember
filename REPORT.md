# Отчёт: этап 2 — каркас Payload CMS и PostgreSQL

## Выполнено в исходниках

- Добавлены зависимости Payload CMS 3, PostgreSQL adapter, Lexical editor и Sharp.
- Добавлена конфигурация Payload в `payload.config.ts`.
- Добавлены маршруты Payload Admin и REST API в App Router.
- Добавлены коллекции Users, Pages, Services, Products, PriceItems, FAQs, Media, Leads.
- Добавлен Global `CompanySettings` с городом Москва и редактируемыми контактами.
- Для услуг, товаров и прайса предусмотрены варианты fixed / range / on-request.
- Публичное создание/изменение заявок через обычные CRUD-права коллекции закрыто. Публичный валидирующий endpoint пока не реализован.
- Добавлены Dockerfile, docker-compose.yml, .dockerignore и пример переменных окружения.
- PostgreSQL в Compose не публикуется на внешний порт; приложение слушает localhost:3000 для будущего reverse proxy.
- Добавлена документация с ограничениями и локальным запуском.

## Что не проверено

В этой среде не запускались `npm install`, `npm run build`, Payload CLI и соединение с PostgreSQL. Поэтому интеграция CMS пока является подготовленным кодовым каркасом, а не подтверждённо работающей установкой. Payload v3 API может требовать небольших корректировок в зависимости от точной версии пакетов, которую установит npm. Следующий обязательный шаг — установить зависимости, сгенерировать import map/types, затем исправить ошибки TypeScript и production build.
