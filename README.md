# Ритуальная служба «Память» — Next.js + Payload CMS (этап интеграции CMS)

Сайт на Next.js App Router с сохранением интерфейса Figma Make, Payload CMS и PostgreSQL. Контент каталога подключён к CMS; форма обратного звонка сохраняет заявки в коллекцию Leads, после чего сервер отправляет настроенные Telegram- и email-уведомления.

## Требования

- Node.js 20.18.1+ (Docker-образ использует Node 22)
- Docker Desktop / Docker Engine с Compose для запуска базы данных
- npm-доступ к реестру пакетов при первой установке

## Локальная разработка

1. Скопируйте `.env.example` в `.env`.
2. Задайте в `.env` `PAYLOAD_SECRET` случайной строкой не короче 32 символов.
3. Для локального запуска приложения на хосте используйте `DATABASE_URL=postgres://payload:change-this-password@localhost:5433/funeral_site`.
4. Запустите базу данных и задайте такой же пароль в `POSTGRES_PASSWORD`:

```bash
docker compose up -d db
npm install
npm run dev
```

Для локального запуска задайте одинаковый пароль в `POSTGRES_PASSWORD` и `DATABASE_URL`; указывайте хост `localhost` и порт `5433`. Compose публикует PostgreSQL только на локальный адрес `127.0.0.1:5433`. Внутри Docker-сети приложение подключается к `db:5432`.

Откройте `http://localhost:3000/admin` для Payload Admin. При первом запуске CMS предложит создать первого пользователя, если миграция/схема БД успешно подготовлена.

## Типы и import map Payload

После установки зависимостей выполните:

```bash
npm run payload:types
npm run payload:importmap
```

Если используемые версии Payload требуют миграций, следуйте результату CLI и создайте/примените миграции до production. Не используйте production-базу для экспериментов.

## Docker Compose

1. Скопируйте `.env.example` в `.env`.
2. Создайте сильные значения `PAYLOAD_SECRET` и `POSTGRES_PASSWORD`.
3. Убедитесь, что `DATABASE_URL` в `.env` настроен для контейнера (hostname `db`).
4. Запустите `docker compose up --build -d`.

Приложение привязано к `127.0.0.1:3000`, а PostgreSQL — к `127.0.0.1:5433`; сервисы не публикуются на внешний интерфейс. Для публичного доступа позже добавьте reverse proxy с HTTPS.

## Заявки и уведомления

Форма обратного звонка отправляет JSON на `POST /api/leads`. Сервер проверяет имя, телефон, email, согласие, длину полей и honeypot; размер запроса ограничен 8 КиБ. Заявка сохраняется через Payload Local API до попыток уведомления. Сбой Telegram или SMTP не отменяет сохранение; состояние каждого канала и общий результат отображаются в документе заявки.

Задайте при необходимости в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
SMTP_HOST=
SMTP_PORT=587
SMTP_USER=
SMTP_PASS=
EMAIL_FROM=
LEADS_EMAIL_TO=
```

Секреты доступны только серверу приложения и не должны публиковаться. Переменные приложения передаются контейнеру через `env_file: .env`; PostgreSQL хранится в Docker volume `postgres_data`. Очередь и распределённое ограничение частоты запросов не добавлялись: в проекте нет общей Redis/DB rate-limit инфраструктуры, а ограничитель в памяти ненадёжен при перезапуске или масштабировании. Для публичного production-сайта настройте rate limit на reverse proxy/WAF либо добавьте общий backend для лимитов.

Читать заявки могут только вошедшие сотрудники. Создание через Payload REST/GraphQL закрыто; публичная форма использует только серверный endpoint. Изменение и удаление доступны администраторам. Администратор может повторить доставку неотправленного канала через Payload API, не создавая заявку повторно:

```bash
curl -X POST http://localhost:3000/api/leads/LEAD_ID/retry-notifications \
  -H "Cookie: payload-token=ADMIN_SESSION_TOKEN"
```

Для проверки формы используйте `/contacts`; успех показывается только после сохранения. Повторное уведомление при недоступном канале оставляет заявку в CMS с `failed`/`partial`, а повтор запроса администратором работает с тем же ID.

## Коллекции CMS

- Users — пользователи админки
- Pages — страницы и SEO
- Services — услуги
- Products — каталог товаров
- PriceItems — позиции прайса
- FAQs — вопросы и ответы
- Media — изображения
- Leads — заявки и статусы уведомлений
- Global CompanySettings — контакты и настройки организации

Настройки CompanySettings используются на публичном сайте: название и город выводятся в шапке и метаданных, девиз — под названием, загруженный логотип — вместо буквенного знака, телефон — в ссылках для звонка, а дополнительные контакты и режим работы — в разделе контактов и подвале. Изменения в админке применяются без правок кода.

Услуги, товары и позиции прайса поддерживают публикацию и черновики. Публичное чтение ограничено опубликованными записями; создание и изменение требуют входа, удаление доступно только администраторам. Цены проверяются на сервере: фиксированная цена неотрицательна, а диапазон содержит обе неотрицательные границы в правильном порядке. У товаров используются поля `images` и `isAvailable`; прежние `gallery` и `available` сохранены, значения из них автоматически в новые поля не копируются.

Опубликованные записи коллекции Pages доступны на сайте по адресу `/<slug>` и добавляются в sitemap; черновики не отображаются. Для slug используйте строчные латинские буквы, цифры и дефисы; адреса существующих разделов зарезервированы.

Для услуг и позиций прайса можно задать необязательное поле «Ссылка на страницу (slug)». Укажите slug существующей опубликованной страницы Pages — карточка услуги или название позиции прайса станет ссылкой на неё.

Изображения сохраняются в Docker volume `media_data`. Добавление полей в production-схему требует создания и проверки миграции; не применяйте миграции к production-базе без резервной копии.

## Перед запуском на VPS

- Перевод оставшихся публичных разделов на данные из CMS; записи Pages публикуются по URL `/<slug>`.
- Укажите реальный домен в `NEXT_PUBLIC_SITE_URL`, установите HTTPS reverse proxy и настройте безопасную политику резервного копирования PostgreSQL.
- Настройте Telegram Bot API: создайте бота и передайте его токен и нужный chat ID только через защищённый `.env`/secret store VPS.
- Настройте SMTP-провайдера и подтвердите адрес `EMAIL_FROM`; передавайте пароль через secret store.
- Сформируйте и проверьте миграции Payload для уже существующей production-схемы до выкладки новых полей Leads. Не запускайте миграции без резервной копии.
- Проверьте утверждённые тексты согласия и политики обработки персональных данных, а также требования законодательства РФ.
