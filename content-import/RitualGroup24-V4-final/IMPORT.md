# Локальный импорт RitualGroup24 V4

Распакуйте каталог целиком. Для чтения достаточно открыть `preview.html` в браузере. Для импорта нужны код проекта с командами `content:check` и `content:import`, установленные зависимости из lock-файла, Node.js 24 и отдельная локальная PostgreSQL с применёнными миграциями проекта. Проверенная версия адаптера и CMS зафиксирована в lock-файле репозитория.

## Проверка файлов

Из корня проекта выполните команду. По умолчанию она читает комплект из `content-import/RitualGroup24-V4-final`.

```powershell
npm.cmd run content:check
```

Для распакованного комплекта в другом месте передайте папку, внутри которой находится `import-all.json`.

```powershell
npm.cmd run content:check -- --bundle "D:\Review\RitualGroup24-V4-final"
```

Проверка сопоставляет сводный JSON с десятью отдельными файлами, каталогом, картой заголовков и семантикой. Она читает WebP, проверяет SHA-256, типы узлов Lexical, владельцев файлов, адреса ссылок, количество FAQ и видимый объём каждой страницы. Обычный dry-run работает без базы.

## Подготовка локальной базы и загрузка

Команды ниже предназначены для PowerShell. Используйте адрес своей отдельной локальной базы. Импортёр принимает явно заданный `CONTENT_IMPORT_DATABASE_URL` с loopback-адресом и проверяет уже установленную схему. Миграции выполняют отдельно штатной командой проекта только для выбранной тестовой базы.

```powershell
$env:CONTENT_IMPORT_DATABASE_URL = Read-Host 'URI изолированной локальной PostgreSQL'
$env:CONTENT_IMPORT_MEDIA_DIR = Join-Path $env:TEMP 'remember-v4-review-media'
$env:PAYLOAD_SECRET = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
npm.cmd run content:check -- --database
npm.cmd run content:import
npm.cmd run content:import
```

Для существующей локальной установки используйте её собственный секрет. Для новой пустой тестовой базы перед проверкой с базой установите `$env:DATABASE_URL = $env:CONTENT_IMPORT_DATABASE_URL` и выполните `npm.cmd run payload:migrate`.

Параметр `--bundle` доступен также при проверке базы и при фактическом импорте. При проверке с базой выводятся числа найденных документов и необходимых привязок Media. Каталог из `CONTENT_IMPORT_MEDIA_DIR` предназначен для отдельного тестового хранилища. Для просмотра загрузок в локальной CMS у неё должен быть доступ к тем же файлам. Без этого параметра импорт использует штатную папку коллекции Media. В Bash задайте переменные через `export` и используйте `npm` вместо `npm.cmd`.

## Документы и связи

1. Импортёр проверяет весь комплект, существующие записи и совместимость связей. Вне режима обновления он пропускает найденные записи. Совпадение имени карточки с другой посадочной требует разбора указанной в отчёте связи.
2. Оригиналы для показа и OG загружаются через Payload Local API. Имя Media включает роль, часть SHA-256 и имя файла. Существующий файл сверяется с источником с учётом штатного перекодирования WebP в Payload. Шесть сохранённых исходников кадрирования из `source-images` предназначены для редакционного архива.
3. В одной транзакции создаются черновики Pages, затем неактивные категории и черновики Services. У категории ключом служит уникальное название из справочника. Её адрес хранит связанная Page. Числовые идентификаторы берутся из текущей базы.
4. После создания документов импортёр заполняет страницы и SEO. Строки в `serviceCategory`, `fields.category`, `fields.doc.value`, `upload.value`, `ogImage` и `openGraph.image` в пакете являются ключами для разрешения связей. В CMS на этих местах записываются ID. Внутренние адреса получаются через штатный маршрут `/[slug]`.
5. Повторный запуск по умолчанию пропускает уже созданные документы. В случае ошибки смотрите `stage`, `error`, при наличии — `details`; команда возвращает ненулевой код. Для сохранения полного журнала в PowerShell добавьте `2>&1 | Tee-Object -FilePath v4-import.log`. Ошибка записи графа откатывает транзакцию целиком. Успешные загрузки Media остаются доступными для повторного использования.

Во время записи папку Media защищает файл `.v4-import.lock` с PID процесса. При аварийном завершении сначала убедитесь, что именно этот импорт завершён и хранилище свободно. Тогда остаточный файл блокировки можно убрать перед повтором. Если имя файла уже занято содержимым вне реестра Media, импорт остановится с указанием имени.

### Явное обновление черновиков

Следующая команда заменяет поля V4 в найденных черновиках Pages и Services. Используйте её только после проверки выбранной базы, если требуется заменить локальную редакцию. Активность существующих категорий и метаданные ранее загруженных файлов сохраняются. Для замены используются оба флага.

```powershell
npm.cmd run content:import -- --update-drafts --confirm-update
```

## Редакторская проверка

В админке проверьте связанную Page категории, категорию и Page каждой услуги. В редакторе страницы категории блок «Услуги категории» использует представление «Заголовки со ссылками и описаниями». Подпись H3 берётся из связанной посадочной, абзац под ней — из краткого описания карточки услуги. Для существующих блоков продолжает действовать режим списка. В превью доступны все проектируемые переходы; публичный рендерер открывает только доступные цели.

У новых страниц установлены `draft` и флаги robots со значениями `false`. У категорий отсутствует версия draft в схеме Payload, поэтому они создаются неактивными. Загрузка Media следует действующим правилам чтения медиатеки. Включение индексации, активация категорий и публикация материалов требуют самостоятельного редакторского решения.
